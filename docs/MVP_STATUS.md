# План и фактическое состояние AutoWatcher

## Текущая задача

Проверяемый цикл `SearchProfile → FakeListingSource → MatchingService → SQLite → NotificationOutbox`.
Это первый срез будущего MVP, а не готовый продукт по всем критериям Windows / Telegram / реальные площадки.

## Фактическое состояние

Код цикла, тестовая доставка, новая миграция V2, тесты и команды проверки добавлены.
Фиктивный источник включается профилем demo; реальные сайты не запрашиваются.
Проверено на GitHub runners Windows/Linux с Java 21: clean verify, 15 тестов без ошибок,
запуск собранного JAR и HTTP demo-цикл. Кодовый коммит: `1a36915d6c63b4e90fd4050838726fad73856b5b`.
[Подтверждение CI](https://github.com/DeksFleks/AutoWatcher/actions/runs/43976099226).

## Инварианты и ограничения среза

- Миграция V1 сохранена. V2 добавляет результаты сопоставления и тестовые квитанции.
- UNKNOWN сохраняется для диагностики и не ставится в очередь.
- Отдельная транзакция на страницу; внешнее чтение выполняется без транзакции БД.
- При ошибке следующей страницы предыдущие сохраняются; новый запуск не дублирует события.
- Мониторинг сериализован внутри одного процесса. Несколько экземпляров на одной БД не поддерживаются.
- Неизвестный или выключенный источник даёт FAILED; выключенный профиль отклоняется до запуска.
- Тестовый транспорт не отправляет Telegram и не имитирует сетевые гарантии.
- Очистка сохраняет компактные строки объявлений и журналы; автоматическое расписание очистки отсутствует.
