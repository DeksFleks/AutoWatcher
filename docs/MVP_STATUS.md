# AutoWatcher — фактическое состояние

## Реализовано в коде

- Проверенный ранее цикл FakeListingSource → MatchingService → SQLite → outbox.
- CRUD профилей в веб-панели и Telegram через общие прикладные сервисы.
- Сохраняемые ссылки поиска и расписание, ручная очередь проверок.
- Привязка единственного владельца Telegram одноразовым кодом с ограниченным сроком.
- Долговечная очередь ответов на команды и Telegram-уведомлений, retry/backoff, ручной повтор DEAD.
- Автоматическая очистка деталей без потери дедупликации.
- Публичные HTTP-адаптеры Авито/Авто.ру с проверкой robots.txt, таймаутами и ограничением частоты.
- Явные ошибки блокировок/изменения разметки; отсутствующие поля остаются UNKNOWN.
- Локальная веб-панель, защита сессии и проверка Host/Origin.
- Windows app-image через jpackage со встроенной Java, трей, открытие браузера, скрипты автозапуска.
- Папка данных пользователя, блокировка второго экземпляра, завершение Spring и восстановление RUNNING.
- Flyway V3; V1 и V2 не менялись.

## Ограничения готовности

Полный MVP по пользовательскому критерию нельзя объявить готовым до подтверждения реальных площадок.
Тесты HTML-парсеров используют контролируемые фикстуры; это не проверка живых сайтов.
Если robots.txt, блокировка или CAPTCHA препятствуют доступу, адаптер не обходит их.
Реальное подключение Telegram требует токена и действий владельца; в CI используется mock Bot API.
Доставка во внешний сервис at-least-once; повтор при аварии после отправки до ACK возможен.
