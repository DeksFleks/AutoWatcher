# AutoWatcher для Windows

1. Скачай артефакт AutoWatcher-Windows-x64 в успешном запуске GitHub Actions и распакуй ZIP.
2. Запусти AutoWatcher.exe. Java включена в пакет; отдельно устанавливать Java/Maven не нужно.
3. Откроется http://127.0.0.1:8080. Если браузер не открылся, открой адрес вручную.
4. В «Настройки» сохрани токен своего бота от @BotFather. Отправь боту показанную команду /start в личном чате.
5. Создай фильтр, выбери площадки и вставь ссылки на поисковую выдачу из браузера.
6. Включи расписание или нажми «Проверить». Результаты и ошибки видны в панели и по /results, /runs в Telegram.
7. Выход — значок AutoWatcher в трее → Exit или Ctrl+C в консоли. Закрытие вкладки не останавливает мониторинг.

Публичные площадки могут ограничивать автоматические запросы. CAPTCHA, HTTP 403/429,
запрет robots.txt или изменение разметки показываются как ошибка, а не как пустая выдача.
Приложение не обходит ограничения. Если нужные поля отсутствуют, результат UNKNOWN не уведомляет.

## Данные и обновление

Данные и журнал: %APPDATA%/AutoWatcher. Токен бота хранится в локальной БД и не отдаётся через API.
Доступ к этой папке должен оставаться только у твоей учётной записи Windows.
Перед обновлением заверши приложение и скопируй папку данных в резервную копию.
Распакуй новую версию отдельно, затем запусти её — Flyway применит новые миграции.
Не откатывай старую версию приложения поверх уже обновлённой схемы; восстанавливай резервную копию БД.
Нельзя одновременно запускать два экземпляра.

## Автозапуск

Автозапуск не включается без твоего действия. В распакованной папке:
`powershell -File .\\enable-autostart.ps1`.
Отключение: `powershell -File .\\disable-autostart.ps1`.
После перемещения папки повторно включи автозапуск.

## Telegram

/help содержит примеры создания и редактирования фильтров с JSON.
Команды доступны только привязанному владельцу в личном чате.
Все изменения сразу видны в браузере.
Для повторной привязки к другому владельцу отключи бота и подключи заново.

Внешняя доставка имеет гарантию at-least-once: при сбое между принятием сообщения
Telegram и записью подтверждения возможен повтор. Идентификатор события указан в сообщении.
Ошибки отправки повторяются с увеличением задержки; после 10 попыток событие видно как DEAD.
Кнопка повторной отправки в истории возвращает его в очередь.

Пакет не подписан коммерческим сертификатом Windows.
